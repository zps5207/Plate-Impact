# Fiber-volume interface

The inspected VUEL receives all material data through Abaqus `props` and contains no `UEXTERNALDB`, file open, or common-block ingestion route for fiber-volume corrections. embmesh therefore writes a deterministic CSV with columns `instance,element_label,host_volume,fiber_volume,volume_fraction,length_t0,length_t90`; a future companion UEL adapter can ingest this file without changing the copied UEL formulation. The `instance` column disambiguates `element_label` when the same part is instanced more than once (each instance's host elements otherwise reuse the same part-local labels).

`fiber_volume`/`volume_fraction` in this file are a **centerline-length x full-cross-section-area approximation**: for each fiber, the length of its centerline clipped to a host is multiplied by the fiber's full circular cross-section area, which implicitly assumes the *entire* disk is inside that host wherever the centerline is. That is exact when a fiber runs comfortably clear of any host face, but over- or under-counts a host's true share when a fiber runs near a face/edge/corner (part of the disk geometrically belongs to a neighboring host) or when the host is smaller than the fiber pitch.

`embmesh visualize --precise-volume` additionally writes `fiber_volume_precise.csv` (columns `instance,element_label,host_volume,fiber_volume_precise,volume_fraction_precise,volume_t0,volume_t90`) using true cross-section-weighted cylinder/hex intersection volume (`embmesh.geometry.swept_cylinder_hex_volume`): each fiber's disk is sampled with a deterministic equal-area polar pattern at several stations along its clipped length, so a host only gets credit for the actual fraction of the disk geometrically inside it. This is slower (opt-in) but does not produce the >1-volume-fraction artifacts the length-based approximation can show for tightly packed or boundary-straddling layouts, and is the more suitable input if the eventual VUEL correction needs an accurate per-element volume rather than a fast approximate one. See `embmesh/geometry.py`'s `swept_cylinder_hex_volume` docstring for its own known (small, bounded, documented) residual limitation.

The current VUEL also has no element-ID lookup or per-element property table. Therefore it cannot consume the CSV directly: the correction output is produced and documented, but applying it requires a companion UEL/VUEL revision that reads the table (or a preprocessing step that supplies one property tuple per element). The mesher does not silently alter the formulation.
