# T-034
role: drafter
round: 1
goal: Let `embmesh plywise` generate the cohesive `*Surface Interaction` itself from a material preset (Dyneema HB26, Hazzard et al. 2018) using the actual ply thickness, instead of requiring the user's deck to already contain one.

## Context (read first)
- `embmesh/cohesive_materials.py` (written and tested by the Hub, do not change the numbers; fix real bugs only and report them): `cohesive_interaction(material, ply_thickness, units, rate, name)` returns a `CohesiveInteraction` with `.inp_lines()`, `.k`, `.strength`, `.fracture_energy`, `.warnings`. Its docstring explains the paper's equations (K_I = E_m / t_SL, K_II = 0.6 K_I, thickness-independent strengths and fracture energies, quasi-static vs ballistic mode II strength) and which values are inferred. The paper PDF is `1-s2.0-S1359835X18303555-main.pdf` in the project root (section 2.5, Table 5, Table 7) if you want to check.
- `embmesh/plywise.py::write_plywise_deck` (the `cohesion` parameter currently only references an interaction that must already exist in the deck, via `embmesh/plycohesive.py`), `embmesh/cli.py` plywise subparser. `Meshing/stack.inp` lines ~59670-59680 show where CAE puts `*Surface Interaction` blocks (after materials, before boundary conditions and the first `*Step`).
- Test decks: `Meshing/plate1hex_curved_ball.inp` (contains a `Cohesion` interaction at the end, SI units: metres/Pa).

## Deliverable (under outbox/T-034/, mirroring the project)
1. In `write_plywise_deck` + CLI: new options `cohesive_material` (CLI `--cohesive-material dyneema-hb26`), `cohesive_rate` (`--cohesive-rate quasi-static|ballistic`, default quasi-static), `cohesive_name` (`--cohesive-name`, default from the preset), `length_units` (`--length-units m|mm`, default `m`; warn loudly in the report if the resulting ply thickness is > 0.5 in `m` mode or < 1e-3 in `mm` mode, since the unit choice is probably wrong), and `cohesive_overwrite` (`--cohesive-overwrite`).
2. When `cohesive_material` is given: compute the interaction from `meta['resulting_ply_thickness']`, insert its `.inp_lines()` into the written deck before the first `*Step` (right after the last `*Material` block if one exists, else immediately before `*Step`), and use that interaction name for the cohesive `*Contact Pair`s. This implies cohesion on; `--cohesion` alone keeps today's behavior (reference an existing interaction). If an interaction with that name already exists in the deck: error with a clear message unless `cohesive_overwrite`, in which case replace that block in place (keep everything else). Never touch other interactions. Put `cohesive_interaction` (name, material, rate, thickness used, units, K, strength, energy, warnings) into the returned meta/report, and add the preset's `warnings` to `meta['warnings']`.
3. The ball contact already avoids cohesive interactions (`plywise_contact`), make sure the generated one is correctly recognised as cohesive there (it contains `*Cohesive Behavior`) and add a test.
4. Tests in `tests/test_plywise_cohesive_material.py`: generated interaction values for a 1 mm ply in `mm` units equal the paper's Table 5; same deck with a 0.1375 mm ply in `m` units reproduces the `Cohesion` block already in `Meshing/stack.inp` (4.36e11, 2.62e11, 1.2e6, 1.8e6, 544, 1088 to 3 significant figures); name collision errors without overwrite and replaces with it; the block lands before `*Step`; contact pairs reference the generated name; unit-mismatch warning fires; the written deck re-parses; the existing suite still passes (state the count; baseline 93).
5. Run once on `Meshing/plate1hex_curved_ball.inp` with 4 plies, `--cohesive-material dyneema-hb26 --cohesive-overwrite --cohesive-name Cohesion` and paste the generated block and the report section into the RESULT.
