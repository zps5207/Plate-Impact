role: drafter
round: 1
goal: Independently review and test Codex's (Refiner's) already-drafted
mesher ghost-host VUEL + fiber-volume work before it's applied to the
project tree, and report bugs/gaps back — do not edit Codex's files.

## Inputs
- `agents/refiner/outbox/MESHER_VUEL_GHOST_TASK_2026-10-01/` — Codex's
  deliverable: a full working copy of the repo with the new
  `embmesh/vuelghost.py`, CLI flags `--host-mode vuel-ghost` /
  `--ghost-scale`, `generate.py`/`writers.py` wiring, a modified
  `uel/VUEL_failure.for` (nsvars 106 -> 107, `svars(107) =
  FIBER_VOL_FRAC`), and new tests (`tests/test_vuelghost.py`,
  `tests/test_vumat_fibers.py`). No `RESULT.md` has been written for this
  yet, so treat it as in-progress, not finished.
- The original task spec: `agents/refiner/inbox/MESHER_VUEL_GHOST_TASK_2026-10-01.md`
  (same brief Codex is working from — read it for full context: ghost
  C3D8R scaled ~1e-4 in E and rho to preserve wave speed while
  contributing negligible stiffness/mass, fiber volume fraction routed in
  as a per-element state variable rather than a prop, and a death-time
  tolerance of +-1 explicit increment between the VUEL's own failure and
  the ghost's native ductile-damage deletion).
- `Meshing/Flat.inp` — the only verification geometry in scope right now
  (curved layups are out of scope, not yet verified in the mesher).

## Deliverable
Work entirely inside Codex's outbox copy (don't touch the live project
tree, and don't edit any of Codex's files — this is a review, not a
fix):
1. Run the existing test suite there (`pytest`) and record pass/fail.
2. Generate a `vuel-ghost`-mode deck from `Meshing/Flat.inp` using the new
   CLI flag (there's already a `Flat-vuel-ghost/` output directory
   appearing there — check what it already produced, and reproduce/extend
   as needed).
3. Check the generated `.inp` and `VUEL_failure.for` against the original
   brief's point-by-point requirements, especially:
   - Is the ghost's elastic modulus and density actually both scaled by
     the same ~1e-4 factor (wave speed `sqrt(E/rho)` preserved, not just
     one of the two scaled)?
   - Does `*UEL Property` stay within the 8-values-per-line limit, and
     does the user-element type key start with `VU`? (Two confirmed real
     Abaqus quirks, in `docs/abaqus-explicit-quirks.md` — check the
     generated deck directly, don't just trust the code.)
   - Is `svars(107)` actually initialized per-element via `*Initial
     Conditions, TYPE=SOLUTION` in the generated deck, with values that
     match `fiber_volume.csv`'s `volume_fraction` column for the
     corresponding elements?
   - Does the ghost's native material actually include `*Damage
     Initiation, criterion=DUCTILE` + `*Damage Evolution` + element
     deletion, or is deletion only nominally wired without real
     calibration?
4. Write up every bug, gap, or place where the implementation diverges
   from the brief — including anything Codex's own tests don't actually
   cover. Be specific: file, line, what's wrong or missing.
5. Put your findings in `agents/drafter/outbox/T-001/` (notes, any
   command output/logs you want to keep), and write
   `agents/drafter/outbox/T-001-RESULT.md` last, per
   `agents/PROTOCOL.md`'s result format.
