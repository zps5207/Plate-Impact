## Context
Vals plywise laminate, 20 plies, ball at -1000 m/s, 70 us. Two runs: VUEL host (job 56574395, `Meshing/vals-plywise/vuel/output.inp`, `uel/VUEL_material.for`) and native host (job 56574397, `Meshing/vals-plywise/native/output.inp`). Both completed, both perforated, but the user sees fibers blowing up (huge node speeds, stretching) instead of deleting. Last-frame numbers: host node speeds up to 77 km/s (VUEL) / 42 km/s (native), fiber nodes displaced >50 mm: 1,100 vs 3, ALLKE 366 J / 56 J against a 3.5 J ball, ETOTAL negative. See `reports/VALS_PLYWISE_VUEL_VS_NATIVE_REPORT.html`.
Leads to check, not conclusions:
- The `Fiber` material (native deck line ~126154) has `*Damage Initiation, criterion=DUCTILE` and no `*Damage Evolution`, and there is no `*Section Controls` deletion. Does Abaqus/Explicit then ever delete a fiber element? What does `*Damage Initiation` alone do in Explicit (output only)? Also `*Plastic` was edited to a single static curve (3.5e9 Pa yield, see lines ~126163-126166).
- Fibers are `*Embedded Element` beams (B31 or similar, check) in a host that is deleted. What happens to an embedded element whose host element is deleted (Abaqus embedded-element constraint: the embedded nodes lose their host and become free? stay constrained to the remaining host?) and how does that interact with the VUEL ghost-deletion path (the VUEL cannot trigger native deletion, see `docs/` and memory-style notes in `agents/refiner/inbox/*VUEL*`)?
- Mass: with the volume correction the VUEL host mass is scaled; beam mass at deleted host nodes; lumped mass left on nodes of deleted elements.
- Does the fiber VUMAT work (T-041, `vumat/VUMAT_fiber_rd.for`, not yet used in these runs) change the answer?
Abaqus facts must come from the decks, the docs in the repo, `agents/ROAR_KNOWLEDGE.md`, or what the user has confirmed on real Abaqus (see `docs/BUGS.md`); do not invent Abaqus behavior, and label anything from general knowledge as unverified.
