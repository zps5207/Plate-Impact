# T-018
role: drafter
round: 1
goal: Make playback in the browser viewer (`verification/roar/odb_viewer_web.py`) smooth. The user reports it jumps about 12 frames every 0.5 s, so it plays like a slide show instead of a video.

## Inputs
- `verification/roar/odb_viewer_web.py` (your T-014 deliverable, now copied there), especially `animation_loop` (around line 613): it advances `frames_to_advance = max(1, int(dt / target_interval))` frames each tick, so when a rendered frame takes longer than the interval it SKIPS frames; and it calls `ctrl.view_update()` without waiting for the browser to receive the previous image. Suspect causes: no flow control with the remote-render stream (frames queue up or are dropped, then the browser catches up in a burst), the remote view's interactive/still render quality switching, and wall-clock-based frame skipping.
- `verification/roar/odb_viewer.py` (do not edit; subclass or work around).
- Real data: `agents/drafter/inbox/T-012/v500_viewer.npz` (150 frames, 0 to 70 us).
- You used headless Edge via CDP before; reuse that to MEASURE what the browser actually shows.

## Deliverable
`outbox/T-018/odb_viewer_web.py` (full updated script) and `outbox/T-018/RESULT-NOTES.md`.
1. Measure first: in headless Edge on the real file, record the frame index shown in the browser over about 15 s of playback (for example, read the displayed frame label or count image updates via CDP/JS), and report delivered fps, the largest gap between consecutive displayed frames, and the number of skipped frame indices, before and after your fix.
2. Fix so playback shows EVERY frame in order at a steady rate. Target: steady 24 to 30 fps at speed 1x on the real file, no multi-frame jumps, no burst-and-stall. Speed control should change the rate (or frames per tick at high speeds) without stutter. If the full 150 frames at 30 fps is too fast, keep the existing default speed meaning and say what it is.
3. Ideas to try, in order of cost (you decide, measure, and report which worked): (a) never skip frames at speed <= 1x, and pace the loop with a fixed-timestep scheduler (`await asyncio.sleep` of the remaining time) instead of dt-driven skipping; (b) flow control: do not push a new frame until the previous remote-view image has been delivered/acknowledged (look at VtkRemoteView options such as `interactive_ratio`, `interactive_quality`, `still_quality`, `still_ratio`, and whether render is being re-triggered by a still-render timer after each update); (c) lower the streamed image quality or size during playback and restore it when paused; (d) local rendering (`--rendering local`) if per-frame payload can be made small enough, report its fps too; (e) any other way that keeps mouse orbit working during playback.
4. Keep every feature as is (controls, drawer, orbit while playing, camera presets). Orbiting while playing must still work and must not break the pacing.
