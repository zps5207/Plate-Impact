# T-019
role: drafter
round: 1
goal: Add a "Record video" feature to the browser viewer that records the animation from the CURRENT viewport (camera angle, zoom, pan) and the current display settings, and gives the user the MP4.

## Inputs
- `agents/drafter/outbox/T-018/odb_viewer_web.py` (your smooth-playback version; if T-018 is not done, STOP and write BLOCKED). Build on it, do not start from the older copy.
- `verification/roar/odb_viewer.py` (do not edit): `ODBViewer.export_mp4` and `export_screenshot` already render offscreen. Reuse that approach.
- Real data: `agents/drafter/inbox/T-012/v500_viewer.npz`.

## Deliverable
`outbox/T-019/odb_viewer_web.py` (full script) and `outbox/T-019/RESULT-NOTES.md`.

1. A Record button (and a small dialog or drawer section) with: resolution (for example 1280x720, 1920x1080, matching current window aspect by default), fps (default 30), frame range (default all; optional start/end), and file name (default `v500_<timestamp>.mp4` or similar, placed in a `recordings/` folder next to the .npz or in the current working directory; say which).
2. Recording uses the camera as it is when the button is pressed: position, focal point, view-up, parallel scale or view angle (zoom), and clipping. A free orbit or zoom before pressing must carry through exactly. If the browser zoom/FOV and the offscreen render differ (aspect ratio changes), keep the same field of view of the subject and say how you handled the aspect.
3. Same display settings as on screen: host mode, fibers-only, ball mode, colors, line widths, opacity, edges, background, and the time label overlay (include the overlay in the video, with a toggle).
4. Must not disturb the live view: playback pauses (or is untouched) while recording, the on-screen camera and frame index are restored afterwards, and the user sees progress (frame x of N) and a way to cancel. Rendering runs off the UI thread/event loop (or in small awaited chunks) so the page stays responsive.
5. When done, offer the file: a download link or button in the page, plus print the saved path in the server console.
6. Optional if cheap: a "Save screenshot" button that writes the current view as a PNG at the chosen resolution.

## Constraints
- Write only inside `agents/drafter/`. Do not edit the project tree. No new dependencies beyond installed ones (use the same imageio/ffmpeg route as the desktop export; say what it is).
- Bind to 127.0.0.1 only. Keep all existing features and the T-018 smooth playback unchanged.

## Done when
- On the real v500 file in headless Edge: set a non-default orbit and zoom, press Record, confirm the saved MP4 exists, has the expected frame count and resolution (check with imageio or ffprobe), and that its first frame matches the on-screen view (compare against a screenshot of the same camera; state how close).
- Verify the live view and the playback state are intact after recording, and that cancel works.
- State what you could not verify.
