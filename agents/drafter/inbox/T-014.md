# T-014
role: drafter
round: 1
goal: Add a browser front end to the verified PyVista viewer using trame, so `python odb_viewer_web.py file.npz` starts a local server and opens the animation in the user's browser, with play/pause, scrubbing, orbit/pan/zoom during playback, and the same display options.

## Inputs
- `verification/roar/odb_viewer.py` (accepted in T-013, 1,100+ lines). It has `ODBData` (loads the .npz, precomputes topology, `get_host_faces(frame)`), and `ODBViewer` (builds meshes/actors on a pyvista Plotter, `set_frame`, camera presets, style toggles). Reuse these classes; import them, do not copy or edit the file (you may not edit anything outside agents/drafter/).
- Real data: `agents/drafter/inbox/T-012/v500_viewer.npz` (58 MB, 150 frames, 24,000 host hexes, 14,192 fiber nodes, 3,642 ball nodes). Use it for all testing, not only a synthetic file.
- trame, trame-vtk and trame-vuetify are now installed in the user's Python (pip). pyvista 0.49.1.
- Look and options to match: see `--help` of odb_viewer.py (host mode wireframe/solid/hidden, fibers-only, ball mode, colors, line widths, opacity, edges, camera presets).

## Deliverable
`outbox/T-014/odb_viewer_web.py`, a single script that imports odb_viewer.py (put the verification/roar folder on sys.path via the `--viewer-dir` option or a relative path guess, and say how you did it) and does:
1. `python odb_viewer_web.py file.npz [--port 8080] [--no-browser]` starts the trame server and opens the browser unless `--no-browser`.
2. A trame/vuetify page with the 3D view filling most of the window and a control bar: play/pause, frame slider, step back/forward, speed, loop, time label in microseconds, camera preset buttons (isometric, symmetry, reset), host mode select, fibers-only switch, ball mode select, host opacity, edges toggle, color pickers for host/fiber/ball/background, line width sliders.
3. Playback must not reset the camera, and orbit/pan/zoom with the mouse must keep working while playing. Use a server-side timer (asyncio task or trame's own mechanism) calling `set_frame` and `ctrl.view_update()`; use local rendering if it works well with this data, otherwise remote rendering. Report which you used and the frame rate observed on the real file.
4. Reuse `ODBViewer.set_frame` and the camera presets so the picture is identical to the desktop viewer. If ODBViewer is hard-wired to an interactive plotter window, subclass or wrap it (off-screen Plotter handed to trame's `plotter_ui`) instead of editing odb_viewer.py. If something truly requires changing odb_viewer.py, write the exact proposed patch in the RESULT instead of applying it.

## Constraints
- Write only inside `agents/drafter/`. No new dependencies beyond trame, trame-vtk, trame-vuetify, pyvista, numpy.
- Bind to 127.0.0.1 only.
- Do not rebuild meshes per frame.

## Done when
- The server starts on the real v500 file, you fetch the page with a headless client or equivalent and confirm it serves, and you capture screenshots of the browser view (e.g. with a headless browser if available, otherwise trame's plotter screenshot) at a few frames.
- You state per-frame latency and whether play-while-orbiting works. If you cannot drive a real browser, say exactly what you could not verify; the Hub will test it by hand.
- RESULT lists what was and was not verified, and the exact command to run.
