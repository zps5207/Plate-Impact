# T-053
role: drafter (agy)
round: 1
goal: Add an odd-count through-thickness subdivision (N_t = 1, 3, 5, ...) to the plywise mesher so each 1.27 mm ply carries 3 hex layers of matrix like Valerie's paper, with the fiber layer and all fiber, cohesive, contact and VUEL volume-fraction logic still correct.

## Context
Valerie's paper (`References/Valerie's Paper.pdf`, "Finite Element Modeling") meshes each 1.27 mm matrix layer with 3 hex elements through the thickness, 8880 hexes per layer, 177,600 matrix hexes in total for 20 layers. Our plywise mesher (`embmesh/plywise.py`, `plyfibers.py`, `plycohesive.py`, `plywise_contact.py`, `plywise_vuel.py`, CLI `python -m embmesh.cli plywise`) takes a ONE-hex-thick plate, splits it into N plies by translation, and so gets one hex per ply. The user wants 3 elements per ply as a later variant, after the ball-size fix runs. Not urgent: this will not finish today, so design carefully and report uncertainty.

Design decision already made by the user: only ODD through-thickness counts are accepted (1, 3, 5, ...). Reason: a fiber layer sits at the ply mid-plane. With an odd count the mid-plane lies inside the middle host element, so every fiber node has one unambiguous host element. With an even count the mid-plane falls exactly on a shared element face or node plane, which makes the embedded-element host search ambiguous, splits the fiber's volume between two hosts, and makes the per-element volume-fraction correction (svars(107), Stage 7/T-006) ill-defined. Reject even counts with a clear error message in both CLI and library calls.
