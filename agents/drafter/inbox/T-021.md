# T-021
role: drafter
round: 1
goal: Build a CLIENT-SIDE viewer: the browser receives the node/element data once and draws everything itself with WebGL (three.js) on the user's GPU. Playback, orbit, pan, zoom all run in the browser, no per-frame images from a server. Replaces the server-rendered trame path for viewing (the trame viewer stays as is for now).

## Why
The trame viewer renders every frame on the CPU in Python and streams JPEGs. On the user's real window it is choppy, and after clicking in the viewport the playback stops while the scrubber still works (T-020 patched part of this, not all). The user's idea: ship the node information to the page and re-render in the browser. Local use only, so the old 15 MB Artifact limit does NOT apply; 80 MB of data is fine.

## Inputs
- `docs/INTERACTIVE_VIEWER_PLAN.md`: the feature list and the face-ownership rule. Ignore its quantization/Artifact-size parts unless you need them.
- `embmesh/viewer_assets/`: pinned three.js r147 (three.min.js, OrbitControls, LineSegments2, LineSegmentsGeometry, LineMaterial).
- `verification/roar/odb_viewer.py`: reference for the topology logic (ODBData: face ownership, exterior faces, ball/fiber topology, camera presets/symmetry view, bounds). Do not edit it. Your JS must match its pictures.
- `verification/roar/odb_viewer_web.py`: the trame UI to mirror (controls, drawer, defaults, colors). Do not edit.
- Real data: `agents/drafter/inbox/T-012/v500_viewer.npz` (150 frames, 24,000 host hexes, 27,401 host nodes, 3,642 ball nodes, 14,192 fiber nodes, host_status per frame). A 100 us version (210 frames, two cases) will arrive later with the same format.
- npz format: see `verification/roar/export_odb_viewer.py` docstring.

## Deliverable (in `outbox/T-021/`)
1. `pack_viewer_data.py`: converts the .npz to a folder of web-friendly files: a `manifest.json` (counts, times in us, bounding boxes, plate thickness axis, default colors) and raw little-endian binary files (`host_pos.f32`, `ball_pos.f32`, `fiber_pos.f32`, connectivity/topology as Uint32, `host_status.u8`). Precompute in Python everything topological: unique faces with owner and neighbor element, ball exterior faces, fiber segments, edges for each face. Positions as plain float32 are fine locally (about 80 MB); if you can cheaply make it smaller (delta/uint16), say so but do not trade away correctness.
2. `viewer.html` + `viewer.js` (or one HTML): loads the manifest and binaries with fetch, builds three.js buffers ONCE, and on each frame only updates the position buffers and, when host_status changed since the previous drawn frame, the visible-face/edge index. Per-frame work must be small typed-array operations, not rebuilding geometry.
3. `serve_viewer.py`: tiny local server (127.0.0.1 only, http.server) that serves the viewer folder and data folder and opens the browser (file:// cannot fetch local binaries, which is why a server is needed). Usage `python serve_viewer.py <data folder> [--port 8800]`.
4. Features (match the trame viewer and the plan): play/pause, scrub slider, step, speed, loop, time in us; orbit/pan/zoom at any time INCLUDING during playback with no interruption; camera presets (isometric, symmetry plane with plate vertical, reset); host mode wireframe/solid/hidden (exterior faces only, updated as elements die); fibers-only; ball mode; independent colors for host, fibers, ball, background; independent line widths (thin lines at 1 px are the default; use LineSegments2 fat lines only for widths above 1 and only if fast enough on the full data, otherwise say so); host opacity and edge overlay in solid mode; defaults: host #8C8C8C, fibers #0033CC, ball #606060, white background.
5. Record video in the browser: canvas.captureStream + MediaRecorder from the current view (WebM is fine; say whether MP4 works in Edge/Chrome). Record button that steps through all frames (or a range) at a chosen fps using the CURRENT camera, with a progress indicator and a download link. Plus a Save PNG button. If you judge this too much for round 1, ship items 1 to 4 first and say so.
6. A clear compare mode is NOT needed now.

## Constraints
- Write only inside `agents/drafter/`. Do not edit the project tree. No npm/build step: plain files, three.js loaded from the pinned local copies (copy them into your outbox folder so the viewer is self-contained).
- Bind to 127.0.0.1 only. No external network.
- Orbit while playing must not stall playback, and playback must not reset the camera.
