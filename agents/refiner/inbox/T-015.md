# T-015
role: refiner
round: 1
goal: Find out why 821 of 24,000 host elements in the v500 deck have a fiber volume fraction Vf >= 1 (max 2.27), decide whether that is a bug or expected, and say what to change if it is a bug. Read-only investigation; report only.

## Facts the Hub established (verify, do not just trust)
- Deck: `verification/roar/t_nc/v500/v500_deck.inp` (copy of ROAR `ctv/nc/v500/output.inp`, the deck the v500 run used). Host = 24,000 VU1 elements (labels 1..24000, nodes in `*Part, name=Plate`), per-element Vf is the 107th value of each `Plate-1.<label>` record in `*Initial Conditions, type=SOLUTION` (SVAR107). Fibers are in part EMBFIB (T3D2, sets EMBMESH_FIBERS_T0 and _T90).
- Whole deck: 16,479 elements have Vf > 0, 821 have Vf >= 1, max Vf = 2.27.
- The VUEL (`uel/VUEL_failure.for`, search ETA_VF) uses eta = max(1 - Vf, 1e-6). So elements with Vf >= 1 get essentially zero mass and stiffness. Solver log check: element 402 (Vf = 1.0975) had mass 5.8e-13 kg instead of about 5.8e-7 kg. Mass for the first 432 elements matched rho*(1-Vf)*volume to about 1e-6, so the VUEL is doing what it was told; the question is whether Vf is right.
- Material: density 980 kg/m3 (SI units, metres). Host elements are about 0.6 to 1.0e-9 m3.

## Deliverable
`outbox/T-015/REPORT.md` and any analysis scripts in `outbox/T-015/`. The report must answer:
1. How is Vf computed (formula, fiber radius/area, how a fiber segment's volume is split across the host elements it crosses, whether segments of both T0 and T90 sets are summed, whether overlapping fibers are de-duplicated)?
2. Distribution of Vf in the v500 deck (histogram), and where the Vf >= 1 elements are in the plate (position, near edges/surface/impact zone? in particular do they cluster where fibers are dense or where the mesh is small?).
3. For a few of those elements, hand-check Vf from the deck geometry: sum the fiber segment lengths inside the element times the fiber cross-section, divided by element volume. Does the hand value agree with SVAR107?
4. Verdict: physically real fiber overcrowding (fibers truly overlap, so Vf > 1 is meaningless), a double-count, a units error, or something else. Say how sure you are and what evidence you have.
5. If it is a bug or a modeling problem, propose the minimal fix (code location and change) and what a sensible treatment for crowded elements would be (cap Vf at some value such as 0.9, rather than 1 - 1e-6, etc.). Do NOT edit `embmesh/`. Put proposed patches in the report as diffs.
