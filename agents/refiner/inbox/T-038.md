## How the solid mesher does it today (read first, verified on ROAR at 500 m/s)
- `embmesh/vuelghost.py::convert_to_vuel_ghost(lines, deck, instance, selected_elements, fractions, options)`: converts the host Part's C3D8R elements into `VU1` user elements (`*User Element`, `*Element, type=VU1, elset=EMBMESH_VUEL_HOST`, `*UEL Property`) plus node-coincident ghost C3D8R elements (`EMBMESH_GHOST_HOST`, labels = max+1..., material = host material scaled by `ghost_scale`, default 1e-4: density, modulus and plastic stresses scaled together, mass ratio 1.0001). It remaps element-based `*Surface` elsets on that instance from host to ghost labels, and writes `*Initial Conditions, type=SOLUTION` giving SVAR107 = per-host fiber volume fraction (`fractions`) as `Instance.label`.
- `embmesh/generate.py` lines ~100-135 show the order: fiber volume rows -> `fractions = {label: row[3]}` -> `convert_to_vuel_ghost` -> `embedded_host_labels = [ghost_by_host[l] ...]` -> `append_fibers_to_deck(..., host_labels=embedded_host_labels)` -> ball node contact. Fibers are embedded in the ghosts; the VU1 host stiffness is reduced by the fiber volume fraction so the overlapping volume is not double counted.
- Symmetry: `embmesh/symmetry.py` (`boundary_symmetry_sets`, `fiber_nodes_on_symmetry`) puts fiber nodes lying on the X/Y symmetry planes into the symmetry boundary conditions.

## What the plywise path does today (the gap)
`embmesh/plywise.py::write_plywise_deck` builds one ply Part duplicated as `Ply-1..N` (pure world-frame translations), assembly surfaces `Ply-k_bottom/top`, `plyfibers.py` writes `Fibers-<angle>` parts + `*Embedded Element, host elset=Ply-k.PLY`, cohesive pairs and node ball contact. Hosts are native C3D8R only. The conversion above is written for ONE instance.
