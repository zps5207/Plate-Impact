## The one thing to change from agy's draft

agy's draft sketch multiplies the **entire** `STRESS_TOTAL` (PK2 +
viscous + bulk) by one `DVOL_EFF` in the `FINT` integration (mirroring
the existing single-`DVOL` line). That silently scales down Rayleigh
viscous damping and bulk-viscosity numerical stabilization by
`eta_k` too, which is a real behavior change the human has decided
against (Stage 7 deliberately kept those numerical-stabilization terms
tied to the element's true geometric size, not to the stiffness/volume
correction).

**Required instead: split the integration into two volume-weighted
sums**, evaluated at each Gauss point:
```
FINT(I) = FINT(I) + BL_MAT(J,I) * (STRESS_SCALE*STRESS_PK2(J)) * DVOL_EFF
FINT(I) = FINT(I) + BL_MAT(J,I) * (STRESS_SCALE*(STRESS_VISC(J)+STRESS_BULK(J))) * DVOL_GEOM
```
(exact variable names/structure up to you, but the physical effect must
be: PK2-derived force integrates on `DVOL_EFF = ETA_VF * DVOL_GEOM`;
viscous+bulk-derived force integrates on unscaled `DVOL_GEOM`.)

Carry the same split through the energy/dissipation bookkeeping so it
stays consistent with what's actually being integrated:
- `ELIE` (strain energy) and `PLASTIC_DISSIP`: use `DVOL_EFF` (these are
  physical stored/dissipated energy tied to the real stress response).
- `DAMP_DISSIP` and `BV_DISSIP`: use `DVOL_GEOM` (these account for the
  numerical-stabilization stress, which now integrates on `DVOL_GEOM`).
- Stage 5's post-failure residual compression stiffness contribution to
  `FINT`: use `DVOL_EFF` (it's physical stiffness, same category as
  PK2, not numerical stabilization).
- `svars` storage of per-Gauss-point stress for field output/restart:
  store the physical stress values as today (stress magnitude itself is
  not what's being scaled, only how it's integrated into forces) --
  don't introduce a second scaled copy unless you find an existing
  consumer that needs one.

Keep agy's conclusions on everything else as-is:
- `ETA_VF = DMAX1(1.0D0 - FIBER_VOL_FRAC, 1.0D-6)`, read per-element
  from `svars(KBLOCK,107)` -- already populated by the mesher's existing
  `fiber_volume.csv` -> `*Initial Conditions, TYPE=SOLUTION` pipeline,
  nothing to change there.
- Lumped mass matrix (`jMassCalc`): `ELEMASS = DENS * ELVOL_EFF`
  (host matrix mass reduced to true matrix volume fraction).
- `CHARLEN` for `dtimeStable` and bulk-viscosity pressure `QBULK`:
  `ELVOL_GEOM` only, never `ELVOL_EFF` -- agy's draft already gets this
  right and explains why (shrinking `CHARLEN` would artificially cut
  `dtimeStable`).
- `CWAVE`: unchanged, depends only on `ALAMBDA`/`AMU`/`DENS`.
- All intrinsic material constants (`EMOD`, `ALAMBDA`, `AMU`, `DENS`,
  `SIGY0`, `HMOD`, `CMAT`) stay completely untouched -- the opposite of
  Stage 7, by design.

## Critical requirement: per-element volume fraction, verified not assumed

**Every element in the vectorized `nblock` block must use its own
`eta_k`, read from its own `svars(KBLOCK,107)`.** This must not become a
call-level scalar shared across the block the way `ALAMBDA`/`AMU`/etc.
used to be before Stage 7 fixed that same class of bug. Prove this with
a concrete test, not just by inspection: a multi-element ROAR deck where
at least two elements in the same call have deliberately different
`FIBER_VOL_FRAC` values (e.g. one at `Vf=0.3`, one at `Vf=0.6` within
the same `nblock`), confirming their resulting internal forces/masses
differ by the correct distinct `eta_k` for each, not a single shared
value.

   PK2-derived contribution does -- this is the whole point of the
   split, so verify it directly, don't just trust the code structure.
