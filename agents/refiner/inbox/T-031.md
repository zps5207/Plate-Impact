## What to build (new code in embmesh/plywise_contact.py plus minimal hooks; do not rewrite contact.py's behavior for the non-ply paths, byte-identical output for existing flows)
1. **All plies in the ball contact.** Generalize node-surface creation to a LIST of host instances: PLATE_NSET (or one nset per ply and a node surface containing all of them) must contain the nodes of every `Ply-k`, not just one. Same for fibers: a LIST of fiber instances with their node label ranges. Do not assume T-029's naming yet (T-029, agy, writes `Fibers-<angle>` parts instanced once per ply); define a small dataclass `FiberInstanceRef(instance, node_labels)` and accept a list, with a stub for tests. The thickness values come from the existing `resolve_contact_thickness` (report which host edge it used; for a thin ply say whether the result is sensible versus ply thickness).
2. **Wrong-interaction trap.** `_first_interaction` returns the first `*Surface Interaction` in the deck, which in the user's decks is `Cohesion`. The ball contact must NEVER reuse an interaction that contains `*Cohesive Behavior`. Add an explicit `--ball-interaction NAME` for the plywise path, default = first interaction without `*Cohesive Behavior`, else create the frictionless hard one like today.
3. **Interfaces excluded from general contact.** Ply-to-ply faces are handled by the cohesive `*Contact Pair` (agy's T-030). Your general-contact inclusions must be only (ply node surface, ball surface) and (fiber node surface, ball surface) pairs. Confirm and document that Abaqus/Explicit general contact with a limited inclusion list does not also pair plies with each other, and write down anything you cannot confirm without Abaqus.
4. **Dangling impact-face surface.** When node contact is enabled in the plywise path, any assembly Elset/Surface that still references the removed plate instance (e.g. `_Surf-1_S2`, `Surf-1`) and any `Contact Inclusions`/`Surface Property Assignment` line naming such a surface must be handled: comment out those lines with a `** removed by embmesh plywise: <reason>` marker and list each in the report. If node contact is OFF, leave them and emit a loud warning in the report instead of silently producing an unresolvable deck.
5. **CLI.** Extend the `plywise` subcommand with `--plate-node-contact`, `--ball-instance`, `--contact-thickness`, `--ball-interaction` (same semantics as the existing flags; fiber contact flag accepted but it only does something once fiber instances exist, say so in help).
