# T-011
role: refiner
round: 1
goal: Add an optional, mesher-generated node-based ball contact to the embmesh mesher, CLI and desktop GUI. Two independent checkboxes, "Plate" and "Fibers". For each one checked, the mesher writes a `*Surface, type=NODE` over the entire node set of that item and puts it in contact with the ball. The input deck then needs no contact definitions of its own.

## Why (verified on ROAR, 13 Oct 2026)

With the VUEL+ghost host (`--host-mode vuel-ghost`) a steel ball at 1000 m/s passed through the plate and left "island" ghost elements alive. The cause was the element-based contact surface on the 1e-4-scaled ghost elements: it is too soft and it depends on the ghost elements staying alive. Replacing it with a node-based surface over every plate node fixed it (0 islands, ball slowed, peak ball nodes inside live ghosts 490 to 0 to 19 depending on thickness). Report: `reports/flat_v2_workarounds_report.html`; sweep data: `verification/roar/t_v2/sweep/` (thickness 0 to 9 mm), builder: `verification/roar/make_thickness_sweep.py`, earlier builder: `verification/roar/make_contact_variants.py`.

The human wants this because the VU1 elements are never deleted, so their nodes stay in contact after the host fails. If the first elements to meet the ball fail at very high speed, the contact for the material behind them must not disappear. A node surface over ALL plate nodes and ALL fiber nodes guarantees that. Keep that property: do not filter nodes by element survival.

## What the mesher must do

New options, off by default (existing behaviour and output must be bit-identical when both are off):

| CLI | GUI | Meaning |
|---|---|---|
| `--plate-node-contact` | checkbox "Plate" | node surface over every node of the host instance (all host nodes, including the VU1/ghost nodes) |
| `--fiber-node-contact` | checkbox "Fibers" | node surface over every generated fiber node |
| `--ball-instance NAME` | dropdown, filled from the deck's instances, enabled when either box is ticked | the impactor; its exterior faces form the contact partner |
| `--contact-thickness MM|auto` | optional numeric field, default "auto" | see below |

Both boxes work in `--host-mode native` and `--host-mode vuel-ghost`.

### The input deck needs no contacts

Question the human asked: they want to supply a deck with their boundary conditions and have the mesher complete the contacts. So the mesher must work when the deck has NO `*Surface`, `*Contact`, `*Contact Inclusions` or `*Contact Property Assignment`. The mesher must:

1. Build the ball surface itself: `*Surface, type=ELEMENT, name=EMBMESH_BALL_SURF` followed by the ball instance's element set, which Abaqus resolves to the free exterior faces. (The `*Elset` for the ball instance must exist; create it with the instance qualifier if the deck has none.) This surface is element-based so it follows ball erosion.
2. Write `*Surface, type=NODE, name=EMBMESH_PLATE_NODES` and/or `EMBMESH_FIBER_NODES` over `*Nset` sets the mesher also writes (all nodes of the item).
3. Write the interaction: if the deck has no `*Surface Interaction`, create `EMBMESH_CONTACT` with `*Friction` 0.0 (frictionless; document that) and `*Surface Behavior, pressure-overclosure=HARD`. If the deck has one (the human's Flatv2.inp has `General`, friction 0.01, hard), reuse it, taking the first, and say so in the report.
4. In the step, write or extend the contact block (Abaqus Explicit allows one `*Contact` per step):
   - No `*Contact` in the step: write `*Contact, op=NEW`, `*Contact Inclusions` with `EMBMESH_PLATE_NODES , EMBMESH_BALL_SURF` (and the fiber pair), then `*Contact Property Assignment` / ` ,  , <interaction>`.
   - Existing `*Contact` block (as in `Meshing/Flatv2.inp`, which has Surf-1/Surf-2 element surfaces and an inclusions list): keep everything the user wrote and add the node-surface pairs to the existing `*Contact Inclusions` data lines, and add the thickness assignment inside that same `*Contact` block after the property assignment. Never produce a second `*Contact`.
   - Do not touch existing user surfaces. (A user element surface on the plate is harmless next to the node surface.)

### Keyword forms that passed Abaqus 2024 datacheck (from the sweep)

```
*Surface, type=NODE, name=Surf-Plate-Nodes
plate,
...
*Contact, op=NEW
*Contact Inclusions
Surf-1 , Surf-2
Surf-2 , Surf-1
Surf-1 ,
Surf-2 ,
Surf-Plate-Nodes , Surf-2
*Contact Property Assignment
 ,  , General
*Surface Property Assignment, property=THICKNESS
 Surf-Plate-Nodes, 0.0005
```

`*Surface Property Assignment` must be INSIDE the `*Contact` block (after the property assignment data line); outside it fails datacheck. Thickness 0 means no assignment line at all. The `plate` there was an existing `*Nset` in the deck; the mesher should write its own sets so it does not rely on the deck.

### Thickness (the sweep result)

- Thickness is not what fixes the islands; the node surface is. 0 mm: 19 peak ball nodes inside live ghosts. About 1 mm (about half the 2.08 mm host spacing): 0. Beyond that thickness only adds energy loss and spurious deletion (ghosts deleted 4,964 at 1 mm up to 8,841 at 9 mm, about 37% of the plate).
- So `auto` = 0.5 x the typical host element edge length, computed from the mesh (use the median edge length of the selected host elements; document the definition). Do not hard-code mm; the human will use thicker plates and different meshes.
- Fibers: use the same `auto` rule applied to the fiber segment length OR the host spacing, whichever you judge safer, and state which. Embedded-fiber node surfaces are UNTESTED on Abaqus; flag that in the result and make it easy to change.
- An explicit number overrides `auto` for both surfaces.
