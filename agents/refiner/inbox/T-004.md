# T-004
role: refiner
round: 1
goal: Subdivide each straight fiber row in `embmesh/fibers.py`'s
`flat_disc_fibers` into multiple T3D2 elements, sized relative to the host
mesh's own resolution, instead of the current single edge-to-edge segment
per row.

## Background

`flat_disc_fibers` (`embmesh/fibers.py:94-147`) builds every straight
0/90 fiber row as exactly one 2-point polyline -> one T3D2 element
spanning the row's entire clipped length. That means a fiber either
survives or fails as a single unit under native Abaqus ductile damage --
no way for damage/deletion to localize partway along a real fiber's
length. Curved layups (`embmesh/curved_layup.py`, `_arc_points(...,
seg_len)`) already generate multi-point polylines; `writers.py`'s
`append_fibers_to_deck` (lines ~94-113) already walks `zip(ids[:-1],
ids[1:])` generically over N-point polylines, so it should need no
changes -- verify this rather than assuming it.

## Spec (human-approved, don't redesign)

1. **Target segment length** = cube root of the **median** host element
   volume. Compute hex volume per host element with the existing
   `geometry.hex_volume(points)` (don't reimplement), take the median
   across all host elements in `elems`, cube-root it. Use the median
   (not `elems[0]` or any single element) so this is robust on a mesh
   with any local non-uniformity. Compute this once per `flat_disc_fibers`
   call, before the per-row loop.
2. **Segment count**: for each row's clipped span (the existing per-
   sub-interval `span` already computed in the `t_lo, t_hi` loop at
   `fibers.py:135-145`, i.e. `hi3 - lo3` or equivalent), compute
   `n = max(1, round(span / target_length))`. Target length is a guide
   for picking `n`, nothing more -- it is NOT the literal per-segment
   length afterward.
3. **Actual segment length** = `span / n`, evenly spaced -- i.e. once
   `n` is chosen, redistribute the full span into exactly `n` equal
   segments (`n+1` points). Do not leave a fixed-length chunk plus a
   shorter leftover remainder at one end.
4. Build `Fiber.points` as the resulting `(n+1, 3)` array (replacing the
   current always-2-point `np.array([base + lo3*d, base + hi3*d])`).
5. `Fiber.curvature_data` stays as today for straight fibers (no
   curvature) -- this task is about segment count/spacing only, not
   adding curvature to flat fibers.

## Constraints

- Don't touch `curved_layup.py`'s generators (cylindrical/spherical) --
  they already multi-segment correctly, out of scope here.
- Don't add a CLI flag or override parameter for the target length
  unless you find the median-cube-root heuristic is impossible to
  compute at the point `flat_disc_fibers` is called (it shouldn't be --
  `elems`/`nodes` are already its arguments). If you do find a real
  blocker, stop and report it rather than guessing a workaround.
- This is a geometry/meshing change only -- no VUEL/Fortran changes, no
  Abaqus deck keyword changes beyond the natural effect of more fiber
  elements existing.
- Don't touch `uel/VUEL.for` (production) or anything under Stage 7's
  already-committed work.
