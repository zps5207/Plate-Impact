# T-016
role: refiner
round: 1
goal: Write unit tests for the viewer data code in `verification/roar/odb_viewer.py` (class ODBData and the camera-bounds code), focusing on the places where a silent error would give a plausible-looking but wrong picture.

## Inputs
- `verification/roar/odb_viewer.py` (read it fully; do not edit it).
- `verification/roar/export_odb_viewer.py`: defines the .npz format and, importantly, the host element ORDER: element_order = element types sorted by name, elements in insertion order within a type; `host_status` columns follow that order; `host_conn_<TYPE>` arrays are per type.
- Real data for an end-to-end check: `agents/drafter/inbox/T-012/v500_viewer.npz` (58 MB; use it only in tests that are skipped if the file is missing).
- A synthetic file generator: `agents/drafter/outbox/T-012/make_synthetic_npz.py` (you may read it; build your own small fixtures in your tests rather than depending on it).

## Deliverable
`outbox/T-016/test_odb_viewer.py` (pytest) plus a short `outbox/T-016/NOTES.md`. Tests should import odb_viewer by path (add `verification/roar` to sys.path in the test), and not need a display (do not open a plotter window).

Cover at least:
1. Face ownership on a 2-hex mesh: 11 or so unique faces, shared face has owner and neighbor; with both alive only the exterior faces (10) are drawn; with one dead the dead hex's faces disappear and the shared face becomes exterior for the survivor; both dead gives none.
2. Host status column order: build an npz with TWO host element types (C3D8R and C3D6R) so the "sorted by type name" ordering matters, with a status column for each element, and assert the viewer deletes the intended element and not a different one. If the viewer concatenates conn arrays in a different order than the exporter's element order, that is a real bug: report it.
3. Triangle/wedge (C3D6R) faces: quad vs triangle faces are handled (the plan said triangles repeat the last node).
4. Real-file test (skipped if missing): on v500_viewer.npz, status is 24000 alive at frame 0, 22316 alive at the last frame, no element comes back to life, and the drawn-face count at the last frame is plausible (greater than frame 0 exterior count is NOT guaranteed: just assert it equals the independently computed count from a straightforward Python reference implementation on a few frames).
5. Animation bounds cover host, ball and fibers at all frames (a ball node moved outside the frame-0 box is inside the computed bounds).

## Constraints
- Write only inside `agents/refiner/`. Do not edit the project tree.
- pytest and numpy only; no display. Keep the real-file test under about 60 s.

## Done when
`python -m pytest outbox/T-016/test_odb_viewer.py -q` output is pasted in the RESULT (note which tests were skipped), and any real bug found in odb_viewer.py is described with a failing test and a proposed patch (diff in NOTES.md), not applied.
